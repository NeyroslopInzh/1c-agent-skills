# Проведение как в типовой

Перед использованием посмотри, как проведение сделано в используемой конфигурации. Если отличается от скилла — используй то, как задумано в типовой. В противном случае — скилл.

Образец УТ 11.6: `CommonModules/ПроведениеДокументов`, `CommonModules/Продажи`, документ `РеализацияТоваровУслуг`. Читай эти модули в выгрузке той базы, которую расширяешь. Второй способ провести документ не писать: ни `НаборЗаписей.Записать`, ни `Движения.<Регистр>.Записать`, ни прямой обход записей регистра из `ОбработкаПроведения`.

Пустую таблицу не записывает `ПроведениеДокументов.ОтразитьДвижения`: ключ `Таблица` + имя регистра, пустое значение пропускается. Имя в `ТекстыЗапроса` равно имени регистра. Свою проверку перед `Записать` не добавляй.

## Новый документ

Модуль объекта, область `ОбработчикиСобытий`. Проведение только стартует типовой вызов:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	ПроведениеДокументов.ОбработкаПроведенияДокумента(ЭтотОбъект, Отказ);
КонецПроцедуры

Процедура ОбработкаУдаленияПроведения(Отказ)
	ПроведениеДокументов.ОбработкаУдаленияПроведенияДокумента(ЭтотОбъект, Отказ);
КонецПроцедуры
```

`ПередЗаписью` выходит при `ОбменДанными.Загрузка`, затем вызывает `ПроведениеДокументов.ПередЗаписьюДокумента`. `ПриЗаписи` вызывает `ПроведениеДокументов.ПриЗаписиДокумента`. Чужие вызовы конкретного типового документа (доставка, счета-фактуры) в новый документ не копировать.

Модуль менеджера, `ПрограммныйИнтерфейс` / `Проведение`:

- `ЗарегистрироватьУчетныеМеханизмы` добавляет имя механизма в массив.
- `ДанныеДокументаДляПроведения` собирает `Запрос` и `ТекстыЗапроса` и возвращает `ПроведениеДокументов.ИнициализироватьДанныеДокументаДляПроведения`.

Текст каждого регистра — функция `ТекстЗапросаТаблица<ИмяРегистра>` в `СлужебныеПроцедурыИФункции` / `Проведение`. Первым делом `ПроведениеДокументов.ТребуетсяТаблицаДляДвижений`. Нужная таблица добавляется в `ТекстыЗапроса` под именем регистра.

Общий модуль механизма, `ПрограммныйИнтерфейс` / `Проведение`, как `Продажи`:

- `ПараметрыДляПроведенияДокумента` берёт `ПроведениеДокументов.ПараметрыУчетногоМеханизма()` и кладёт регистры в `ПодчиненныеРегистры`.
- `ОтразитьДвижения` при отказе выходит, иначе вызывает `ПроведениеДокументов.ОтразитьДвижения` по каждому регистру.

Механизм попадает в конфигурацию через `&После("УчетныеМеханизмыКонфигурации")`: `МеханизмыКонфигурации.Вставить("<ИмяМеханизма>", "<ИмяОбщегоМодуля>")`. Методы, которые проводник при таких параметрах не вызывает, не добавлять. `ТекстыЗапросовСторнирования` писать, только если документ участвует в исправлении и у образца эта функция есть.

## Дописка типового документа

Новый обработчик проведения не заводить. Свои движения входят в ту же цепочку:

- `&После("ЗарегистрироватьУчетныеМеханизмы")` добавляет имя механизма;
- `&После("УчетныеМеханизмыКонфигурации")` связывает имя с модулем;
- вызов своего `ТекстЗапросаТаблица...` вставляется в `ДанныеДокументаДляПроведения` через `&ИзменениеИКонтроль` и `#Вставка`;
- модуль механизма тот же, что у нового документа.

Проверка или реквизит вокруг записи — `&Перед` / `&После` типовой `ПередЗаписью`, с тем же выходом при загрузке обмена. Движения из этой процедуры не писать.
